# 待办 · 课程表 App

一个 Android 端的待办与课程表应用。核心是**到点真的会响**的提醒，以及两种录入方式：手动填表，或者直接跟 AI 说一句话。

Flutter 写的，数据全部存在本机。唯一的联网是调用你自己配置的 AI 接口——不配也能用，手动录入完全离线。

## 现在能做什么

**三种条目，混在一个时间线上**

- **课程**：周期规则（精确周次，或每周/单周/双周）+ 地点 + 教师 + 颜色，管一整个学期
- **事件型待办**：考试、讲座、开会这种「到点必须在那」的
- **任务型待办**：写作业、取快递这种「当天做完就行」的

数据层分开存，显示层混排在一起。事件和任务还能标**优先级**（普通/重要/紧急），只做视觉标记——

日程是按时间读的，把紧急的条目提到早上八点的课前面反而乱。

**课表是周网格，左右滑动翻周**

左栏是**节次**（第 N 节 + 起止时刻），和教务系统的「第 3-5 节」对得上；每门课按课名稳定取一个马卡龙色，块里写课名和 `@教室`；8:00 到 21:55 按真实分钟数铺，事件、任务这类不对齐节次的条目也能落在正确高度。

**本周不上的课也画出来**，灰着并标「非本周」——课表的价值是看到全貌，不是只看到这周要上的。翻到别的周时右边会飘一个「回到本周」。

**课表导入：丢文件、丢截图、粘文字都行**

三条入口，产出同一个预览清单：

- **教务系统导出的 `.xls`**——本机直接解析（自己写的 OLE2 + BIFF8 读取器），不联网、不花钱，课表内容不出手机。导出文件里同一门课常因换老师被拆成几块，会按「课名 + 星期 + 时间 + 地点」自动合并、周次取并集（线性代数 `3-12,15-18` 陈哲 + `13-14` 邬恩信 → 一条 `3-18` 周）。
- **课表截图 / 照片**——发给 `deepseek-flash` 识图（多模态，图片 base64 内联）。换成不支持识图的模型会直接提示，不浪费一次请求。
- **粘贴文字 / CSV / TXT**——AI 只负责拆出「周几 + 第几节」，**节次换算成钟点由本机作息表做**：`345` 是三节连上不是三百四十五，`第 0 节` 是本校的第十节，`A/B/C` 是晚上三节。换算一定对，AI 只做它擅长的拆词。

`.xlsx` 不认（新版是 zip 格式），会明确提示「在 Excel/WPS 里另存为 Excel 97-2003 (.xls)」，而不是静默失败。

解析完逐条预览、认不出时间的标红手动补，勾选后才入库，重复导入按「课名 + 星期 + 时间 + 周次」去重。

**周次是真的周次集合，不是单双周**

真实课表里是 `4,6,8,10,12,14,16,18`（偶数周但从第 4 周起）、`3-12,15-18`（跳过 13-14 周）、`3,5-11` 这类写法，「单/双周」根本表达不了。所以每门课存一份周次写法，`WeekSet` 负责解析和压缩；老数据没有周次时回落到单双周。

课程还存**任课教师**——同一门课不同周次换个老师，是大学课表的常态。

作息表（13 小节的起止时间）可以在「我的 → 作息表」里改成自己学校的。

**AI 对话录入**

一句话能出多条草稿：

```
周五17点E栋104考试，周日交作业
```

→ 解析成两条，各自带日期时间地点，逐条确认才入库。

也能吞一长段微信公众号活动通知（带 emoji、报名链接、口号的），抽出「什么事、哪天、几点、在哪」，剩下的进备注。草稿只活在内存里，不确认就不写库。

供应商走 OpenAI 兼容接口，默认 DeepSeek，baseURL / apiKey / model 都能改。

**提醒**

本地通知，Importance 拉满 + `USAGE_ALARM` + `category=alarm`，锁屏可见，声音能绕过静音。重启后自动重新注册闹钟。

**能提前提醒，课程也会响**

事件默认提前 15 分钟（要提前到场），任务默认到点（当天做完即可），课程默认提前 10 分钟（够从宿舍走到教室），
0–60 分钟可选。通知正文写的是**实际还剩多久**，不是配置值——你 14:58 建一条「15:00 考试、提前 5 分钟」，
它会说「还有 2 分钟」，不会骗你说还有 5 分钟。

课程是周期规则，但 Android 的重复闹钟表达不了单双周、也表达不了「学期结束就停」，所以改成把规则
按未来 8 周展开成一条条具体闹钟（每次打开 App 往后续），正文带上教室：`还有 10 分钟：高等数学A（E302）`。

从备份恢复、导入课表、勾掉任务之后都会重排一遍，不会出现「库里改了、闹钟还是旧的」或者「做完了还响」。

**输入体验**

日期时间只敲数字，横杠冒号自动补（`20261121` → `2026-11-21`）。学期起止存成「方案」，新建课程一键套用，按当前日期自动选中学期。

**备份**

导出 JSON 走系统分享，恢复是覆盖式且失败会整体回滚。

## 本地构建

需要 JDK 17、Flutter SDK、Android 命令行 SDK（不需要 Android Studio）。

```bash
cd app
flutter pub get
cd android
# debug（日常开发用，~188MB，带 JIT 快照和热重载）
./gradlew assembleDebug --console=plain --offline
# 产物：app/build/app/outputs/flutter-apk/app-debug.apk

# release（给朋友装 / 备份用，~19MB，AOT 编译）
./gradlew assembleRelease --console=plain -Ptarget-platform=android-arm64
# 产物：app/build/app/outputs/flutter-apk/app-release.apk
```

离线构建依赖本机 maven 仓库（`E:\AndroidDev\local-maven`）里的 Flutter engine jar。

两个坑：

1. `exclusiveContent` 那段必须放在**根工程** `android/build.gradle.kts` 的 `allprojects` 里。只写在 `app/build.gradle.kts` 里，插件子工程（`android_file_picker`、`sqflite_android` 等）解析 `io.flutter:flutter_embedding_release` 时仍会跑去 `storage.googleapis.com`，在慢速网络下表现为卡住。
2. `assembleRelease` **不要加 `--offline`**。release 版的 engine 包是新加进本地仓库的，Gradle 的模块索引还没登记，离线模式下会直接报 `No cached version available for offline mode`。不带 `--offline` 时 `io.flutter` 被锁定在 `file://` 本地仓库，解析全在磁盘上完成，不会联网。

## 已知限制

- **只有 Android**。iOS 没做，因为编译需要 Mac。
- **国产 ROM 的后台冻结是系统级限制**。vivo / 小米 / 华为需要在设置里手动加白名单（App 内「我的」页有指引），否则长息屏后提醒可能不准。这是所有国产安卓 App 的共同问题，绕不过去。
- **贪睡没做**（点通知推迟 N 分钟）。它要通知 action + 后台 isolate，而国产 ROM 上后台访问数据库不可靠，
  做出来大概率时灵时不灵，不如不做。
- **课程提醒只覆盖未来 8 周**，靠每次打开 App 往后续。8 周不开 App 就断——但学生一周会开好几次，
  比「放假了还每周催上课」划算。
- **优先级不参与排序**，只是颜色和标签。
- 课程没有「这门不提醒」的开关，建了就一定提醒。
- **`.xlsx` 不直接支持**，只能 `.xls`。新版格式是 zip + XML，要再写一套解析器；而教务系统都能导出 `.xls`，
  先给一句「另存为」提示更划算。
- **教师字段只在导入预览和编辑页显示**，周网格的格子太小，没地方放。
