# 设计：日程页的过期分区与完成态

> 定稿 2026-11-25。适用于日程页（`lib/screens/schedule_screen.dart`）的**日视图列表**。
> 课表页（周网格）不受影响，保持原样。
>
> **修订 2026-11-26**：课程下课后改为判**已完成**（原为已过期）。课是固定时刻发生的
> 事，上完就是上完，不存在"欠着没做"，不该跟没完成的事件/任务一起堆在过期区。
> 事件/任务的过期规则不变。课程进完成区不播勾选粉尘（时间推进 ≠ 用户勾选）。

---

## 一、要解决的问题

日程页现在把当天所有条目按时间平铺，**已过去的和还没到的混在一起**。到了晚上，
上午的课和晚上的作业并排显示，眼睛还得自己筛一遍才知道还有什么没做。

同时"完成"这件事只存在于任务型待办，事件型待办（考试、讲座）没有勾选入口，
做完了也只能干看着。

**目标**：让"接下来要做什么"永远在最上面，"已经过去/已经做完"自动沉底并可折叠。

---

## 二、三个状态

每个条目（一节课、一个事件、一个任务）在某一时刻只处于三态之一：

| 状态 | 判定 | 视觉 | 位置 |
|---|---|---|---|
| **正常** | 未完成，且判定时间未过 | 原色 | 列表最上（正常区） |
| **已过期** | 事件/任务未完成，且判定时间已过 | 灰 + 淡红左条 | 中段（过期区） |
| **已完成** | 手动勾选完成；**或课程判定时间已过**（下课=上完） | 灰 + 勾 + 删除线 | 最下（完成区） |

**三个区的相对顺序固定**：正常 → 已过期 → 已完成，**永不交错**。

> 为什么"已过期"要排在"已完成"之上：过期的还欠着，完成的已经了了。
> 欠着的应该比了了的更靠前，否则一眼扫下去会以为今天全做完了。
>
> **课程例外（11-26 修订）**：课程没有"欠着"的概念，过了下课时刻直接算完成，
> 永不进"已过期"区。所以"已过期"区现在只可能有事件和任务。

---

## 三、判定时间：两个字段，必须分开

这是最容易写错的地方。

| 字段 | 用途 | 课程 | 事件 | 任务 |
|---|---|---|---|---|
| **排序时间** `sortMinutes` | 决定在区内排第几 | 开始时刻 | 开始时刻 | 截止时刻（无钟点取 24:00） |
| **判定时间** `deadlineMinutes` | 决定过没过期 / 课程是否完成 | **下课时刻** | 开始时刻 | 截止时刻（无钟点取 23:59） |

- 课程在日程里要按**开始时间**排才自然，但**上课中不能算过期**，所以判定用结束时间。
  两者用同一字段一定会出"正在上的课显示成灰的"这种 bug。
- 任务的排序时间沿用现有实现（无钟点 = 24:00，排当天最后），但判定时间取 23:59
  ——`24:00` 和 `23:59` 只在"当天最后一分钟"这一点上不同，取 23:59 更符合"今天之内做完"。

只有**当天**的条目参与判定：

- `day < 今天`：不出现（日程页本来就只查一天）
- `day == 今天`：按 `当前分钟数 > deadlineMinutes` 判定
- `day > 今天`：一定是正常态

---

## 四、排序

三个区**内部**用同一套三级键：

| 级别 | 键 | 方向 |
|---|---|---|
| 1 | `sortMinutes` | 正序（早的在上） |
| 2 | `priority` | 高 → 低（紧急 2 → 重要 1 → 普通 0） |
| 3 | `key` | 字典序，保证稳定（同一时刻多条时不会每次刷新换位置） |

第 2、3 级只在同一时刻有多条时才用得上。

---

## 五、折叠（只管已完成区）

| 已完成条数 | 表现 |
|---|---|
| ≤ 5 | 全部显示，**不出现折叠控件** |
| > 5 | 默认只显示**最近 5 条**（按排序键取末尾 5 条，内部仍正序），上方一条「展开更早的 N 条」 |
| 点击展开 | 全部铺开，控件文案变「收起」 |
| 每次进入页面 | 恢复默认折叠，**不记忆展开状态** |

`N = 总数 − 5`。折叠状态下新勾一条，N 自动 +1。

**为什么取"最近 5 条"而不是"最早 5 条"**：区内正序排列意味着刚完成的那条在最下面，
如果折叠时保留最早 5 条，用户刚做完的东西永远看不见。保留最近 5 条能兼顾
"刚做的看得见"和"整体顺序不乱"。

**已过期区不折叠**。那是欠着的账，折叠会把该处理的事藏起来。

## 六、交互与动画

### 勾选

- **任务型、事件型**都可以勾选（新增事件型的勾选入口）；**课程不可勾选**（上完就是上完，没有"完成"这个动作，时间一到自动进完成区）
- 勾选后：该条目从原区移除，按排序键插入完成区
- **支持取消勾选**：再点一次，按**当前时间重新判定**回到正常区或过期区
- **课程自动完成不播粉尘**：课程进完成区是时间推进的结果（`_completionKey` 跳过课程类型），走普通收展，不播勾选粉尘动画
  （不记"从哪来"，一律重判——这样"提前完成又取消"能正确回到正常区）

### 动画时序

勾选一条**过期条目**（跨越整个过期区）：

| 时刻 | 动作 |
|---|---|
| 0 ms | 勾变实心；立刻落库、立刻重载（不先等动画） |
| 0–1000 ms | 它在**原位置**高度收到 0 + 淡出；下方的条目贴着这个收拢过程**上滑**让位 |
| 0–1000 ms（同时） | 目标位置那条**从高度 0 展开 + 淡入**，把下面的条目**往下推** |
| 1000–1400 ms | 展开演完才开始闪高亮（淡黄 → 透明，400 ms） |
| 1400 ms 后 | 静止 |

取消勾选走同一条时间线，方向相反。**两个方向都要有动画**。

两条不做的事：

- **不做"飞行"**：已过期区在最上面、已完成区在下面，让它从 A 飞到 B 要跨越中间一叠卡片，
  层次会乱（谁盖谁说不清）。原地收起 + 目标处展开，眼睛一样跟得住。
- **换日期不播动画**：那是整页换内容，一次动十几条反而更乱。

> 没有这段动画，一条最上面的过期条目被勾掉后会"凭空消失"——它其实往下跨了
> 十几行的距离，但用户看不到这个过程。
>
> ⚠ 只让"位置真的变了"的行播动画，不能每次数据一变就把整列重排一遍：
> 那样每次都动，眼睛根本分不清哪条动了。

## 七、边界情况

| 情况 | 处理 |
|---|---|
| 无钟点任务 | 判定时间 = 当天 23:59，排序时间 = 24:00 |
| 课程实例跨天 | 只属于当天，第二天不再出现（靠 `expandCourse` 的日期匹配天然实现） |
| 待办过期后 | 一直留着，直到勾完成或删除（不自动消失） |
| 勾选还没到期的事件/任务 | 允许（提前完成），直接进完成区 |
| 取消勾选提前完成的 | 按当前时间重判：未超时回正常区，已超时进过期区 |
| 课程下课时刻 = 当前时刻 | 不算完成（严格大于才算），仍在正常区 |
| 课程下课后 / 过去的课 | 自动进完成区，不进已过期；不播粉尘 |
| 空区 | 不渲染该区的标题和分割线 |

---

## 八、刷新

过期是时间自己走出来的，不是用户点出来的：

- 页面 `initState` 算一次
- 前台每 **60 秒** 重算一次（只重算状态，不重排整个列表，避免闪烁）
- 从其他页切回来时重算（`_load()` 已经做了）

现有代码没有这个定时器，需要新增；课表页已有同类实现（当前时间线每分钟刷新）可参考。

## 十、验收标准

1. 晚上打开日程页，上午上完的课在"已完成"区、灰着、带删除线（11-26 修订，原为已过期）；过点的未完成任务在"已过期"区、灰着、有淡红左条；晚上的作业在"正常"区、原色。
2. 勾一条过期任务，它淡出（0.25s）后出现在完成区并闪一下。
3. 再点一次那个勾，它回到过期区（因为时间已过），不是回到正常区。
4. 勾一条**明天**的事件，它进完成区；取消后回到**正常区**（因为还没到时间）。
5. 已完成区 6 条时，默认只显示 5 条 + 「展开更早的 1 条」；点开显示 6 条。
6. 已完成区 5 条时，不出现任何折叠控件。
7. 课表页（周网格）行为完全不变。
8. `flutter test` 全过，`flutter analyze` 0 问题。
