## 1. 一句话

勾选任务/事件完成后，不再只是"原地收起 + 下方补位"，而是卡片先在原地**碎成粉尘飞散**，散完后下方才滑动补位，粉尘再到**下方已完成区重新聚成卡片**，最后闪一下淡黄高亮。

---

## 2. 需求怎么来的

用户："我想要一个动画，勾选完成后有一种粉碎感。" 前面几轮给的碎块飞散 / 裂成两半 / 捏扁抖动都不是。用户发来一段视频（微信目录里的 `.mp4`，3 秒 30fps）：

- 抽帧看下来，视频不是待办 App，是**通知中心**：一张通知卡片化成极细的蓝色粉尘飘散，最后露出壁纸。
- 用户确认要的就是这个观感："视频原样：散了就没了"，技术选"假粒子（先做）"，补位选"散完再滑动"。
- 最后补一句："**然后在下面重组**" —— 于是从"散了就没了"改成散完后在下方已完成区聚成卡片。

三个关键取舍（用户选项 + 我的默认，都在对话里定过）：
1. 散完再滑动，不是边散边滑；
2. 假粒子（小圆点），不用 shader；
3. 取消勾选**不做**反向粒子，保持普通淡入（低频操作，先把主效果做扎实）。

---

## 3. 动画时序

总长 **2.4 秒**，四段严格先后：

| 段 | 时间 | 效果 | 下方条目 |
|---|---|---|---|
| ① 散开 dissipate | 0–500ms | 源卡片原地碎成粉尘向外飞散，卡片本体淡出 | **纹丝不动** |
| ② 收起 collapse | 500–1200ms | 源行高度收到 0 | 向上滑来补位 |
| ③ 重组 reassemble | 1200–2000ms | 粉尘在已完成区目标位置聚成卡片，卡片淡入 | 不动 |
| ④ 高亮 flash | 2000–2400ms | 聚成的卡片闪一层淡黄 | 不动 |

时长常量在 `app/lib/widgets/day_timeline_list.dart` 顶部：`kBurstDissipate` / `kBurstCollapse` / `kBurstReassemble` / `kBurstFlash`。

---

## 4. 实现要点

### 4.1 两段独立粒子，不做跨屏坐标传递

最初设想是"同一批粒子从原位飞到下方目标位"，需要 `Overlay` + 源/目标 `GlobalKey` 拿屏幕坐标。放弃，原因：

- 列表在 `PageView` 里可滚动、可翻周、可折叠，重排那一瞬间源/目标坐标全是失效的；
- 人眼不会盯着某一粒粉尘跨 1 秒飞行，两段独立粒子观感是连续的；
- 独立粒子不需要任何坐标传递，可测试、稳定。

所以做成两个独立模式：`ParticleMotion.dissipate`（源卡片向外散）、`ParticleMotion.gather`（目标卡片向内聚）。

### 4.2 假粒子组件 `app/lib/widgets/particle_burst.dart`

- `CustomPainter` 画 46 个小圆点，起点/方向/半径/延迟在 `initState` 里按 `seed` 一次性定死。**必须固定随机种子**：用 `Random()` 每次 build 换一批，看着就是闪烁噪点，不是散开。
- seed 用 `entry.key` 的稳定哈希（`_stableHash`，不用 `String.hashCode`，后者跨版本不稳）。
- 每粒有自己的 `delay`，散开有先后，不是齐刷刷一起动。
- 卡片本体的淡入淡出交给粒子组件（`dissipate` 淡出、`gather` 后半段才淡入），`TimelineItem` 有 `burst` 时不再自己套透明度，避免叠两层。
- flash 高亮放在粒子外层：聚拢完成后的临门一脚，顺序上不打架。

### 4.3 状态机（在 `day_timeline_list.dart`）

`_BurstStage` 四态 + `idle`。要点：

1. **认勾选用状态变化，不认 `flashKey`**：`schedule_screen._toggleEntry` 是先 `await` 落库+重载（`_load` 的 setState）、再 setState 设 `flashKey`，两次更新分开。数据先到那一帧 `flashKey` 还是 null，用 key 判断会漏掉。`_completionKey()` 直接比 `_rows` 和 next 每条的 state，谁从非 done 变 done 就是它。
2. **数据立即落库，显示冻结 500ms**：勾选瞬间照旧写库、重载，但列表 `didUpdateWidget` 进入 dissipating 后先 `Timer(500ms)` 按住 `_rows` 不动，下方才不会动。落库不延迟，切走页面也不丢数据。
3. **先 remove 后 insert，中间留空档**：500ms 到点只把源行 `removeItem`（收起补位）；1200ms 到点才 `insertItem` 目标行（带 gather 粒子）。这个空档就是"散完才重组"。
4. **动画期间到来的其它更新**（60 秒 ticker 重算状态）暂存 `_deferredNext`，序列跑完再收敛，避免打断 `AnimatedList` 内部计数导致重复行。
5. **切日期不播**：列表 key 带日期，换日期是整页换实例，不走这套状态机。

### 4.4 `AnimatedList` 的坑（沿用并加深）

- 差异算法仍是新旧 key 序列的 **LCS** 当"不动的行"，其余 remove + insert。不能只删"新列表没有的 key"——跨区移动的行 key 在新列表里是存在的，会插成两份。
- 收起阶段的 remove 时长是 700ms（`kBurstCollapse`）；普通重排（取消勾选、时间推移）仍是 `kRowMoveDuration = 1000ms`。
- 重组阶段插入的目标行**不做高度收展**（否则和粒子聚拢叠在一起像"长出来"），直接全高，淡入交给粒子。它在列表末尾，全高出现不顶动别的行。
- 高亮 `Color.lerp` 终点色必须是同色相全透明版 `0x00FFF1C2`，不能用 `Colors.transparent`（透明黑，中途变脏褐）——沿用上一版的修正，`flash_highlight_test.dart` 钉住。

## 5. 测试

| 文件 | 新增 | 覆盖 |
|---|---|---|
| `app/test/particle_burst_test.dart` | 5 | 两种模式画出 painter / 散开套 dissipate、重组套 gather / 取消勾选不播粒子 / **勾最后一条强制收起不重复** / 散开阶段下方纹丝不动 |
| `app/test/widget_test.dart` | 改 2 | 「勾选沉到已完成区」用显式分段 pump 走完 2.4s；「散完再滑动」钉住散开阶段下方不动、收起阶段中途态 |

- 显式分段 pump 的原因：`pumpAndSettle()` 在两段 Timer 之间那几帧没有 scheduled frame 时会提前返回，2.4s 的 Timer 链走不完。测试里按各段时长逐段 `pump`，再 `pumpAndSettle`。
- 另一个坑：`pump(630ms)` 一大步里，散开的 500ms Timer 在帧中间触发、`removeItem` 动画是 Timer 回调里才创建的，这次 pump 内来不及推进，读到的是起始位置。要拆成「越过 500ms」+「再 pump 350ms」两步。
