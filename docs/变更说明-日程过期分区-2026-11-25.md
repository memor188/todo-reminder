## 3. 用户可见的行为变化

### 3.1 三段与顺序

同一天内固定三段，**顺序不交错**：

```
正常（不上标题）  →  已过期 N  →  已完成 N
```

- 段内一律**按时间正序**（早的在上）。
- 段标题右侧带计数；某段为空时整段不渲染。
- 同一天内课程、事件、任务仍混排（按时间），只是被切成三段。

### 3.2 「过期」的判定

判定与排序用了**两个不同的时刻**，这是本次最容易踩的地方：

| 类型 | 排序用（`sortMinutes`） | 判定用（`deadlineMinutes`） | 理由 |
|---|---|---|---|
| 课程 | 上课时刻 | **下课时刻** | 正在上的课不能算过期 |
| 事件 | 开始时刻 | 开始时刻 | 「到点人得在那」，过了就该催 |
| 任务（有钟点） | 截止时刻 | 截止时刻 | — |
| 任务（无钟点） | 24:00 | **23:59** | 排序摆最后，但不许 23:59 就提前判死 |

判定顺序：已完成 → 完成；日期在今天之后 → 正常；日期在今天之前 → 过期；同一天 → `当前分钟 > 判定时刻` 才过期（**等于不过期**，避免整点那一分钟闪一下）。

### 3.3 勾选

- **事件和任务都能勾**。以前只有任务有勾，事件没有入口。
- **课程不能勾**：上完就是上完，没有「完成」这个动作；过期课程只变灰、带淡红竖条。
- 勾任务时会同时撤掉它的本地提醒（以前勾完了到点还会响）。
- 取消勾选会把条目从已完成放回它该在的位置（按时间重排，不是塞到末尾）。

### 3.4 已完成折叠

- 阈值 5 条：超过才折叠，不超过保持原样。
- 折叠时**保留最近的 5 条**，藏起更早的（区内是正序，所以要砍的是头部而不是尾巴 —— 砍尾巴会让刚勾完的看不见）。
- 折叠条文案：`展开更早的 N 条` / `收起`。
- 展开状态不持久化，切日期即重置为收起。

### 3.5 动画

| 动作 | 效果 | 时长 |
|---|---|---|
| 勾选/取消（原位置） | 卡片**高度收拢到 0 + 淡出**，下方条目贴着这个过程**上滑**让位 | 250 ms |
| 勾选/取消（目标位置） | 卡片**高度 0 → 原高 + 淡入**，把下方条目**往下推** | 250 ms |
| 展开演完之后 | 新位置的卡片闪一层淡黄 | 400 ms |

跨区移动如果没有任何提示，眼睛跟不上它去哪了 —— 这三个动作就是干这个的。

要让位而不是瞬移，这是**必须**的：之前列表是每次数据一变就整列重建，位置变化天生是瞬时的，
用户的原话是「消失后立刻补位，看起来好难受」。

**不做**两件事：

- 不做「从 A 飞到 B」：已过期区在最上面、已完成区在下面，飞行要跨过中间一叠卡片，谁盖谁说不清。
- 切日期不播动画：整页换内容，一次动十几条反而更乱。

### 3.6 自动重算

页面挂 `Timer.periodic(60s)` 重算当天状态，不用退出重进就能看到「刚下课的那门课变灰」。
重算如果导致条目跨区，同样走上面那套收展动画；只是变灰、位置没动的不动。

### 3.7 未改动

周视图（课表页）没动。

## 4. 实现要点

### 4.1 新增的模型 API

```dart
enum EntryState { normal, overdue, done }

EntryState resolveEntryState(entry, {required DateTime day, required DateTime now});

class DaySections { final List<TimelineEntry> normal, overdue, done; }

DaySections buildDaySections({
  required DateTime day,
  required List<Course> courses,
  required List<EventItem> events,
  required List<TaskItem> tasks,
  required DateTime now,
});
```

### 4.2 段内排序的三级键

```
sortMinutes 升序  →  priority 降序（同刻重要的在前）  →  key 升序（稳定，防抖）
```

### 4.3 勾选流程

```
点击 → 落库（task: setTaskDone + 撤提醒；event: setEventDone）
     → _load()                            // 重新分区
     → setState(_flashKey = key)           // 标记待高亮
     → DayTimelineList.didUpdateWidget 算出新旧差异 → 收展动画
     → 展开演完 → 闪 400ms 高亮
```

2026-11-25 之前这里有个 `await Future.delayed(250ms)` 先等淡出再落库。现在不需要了：
动画由列表自己按差异驱动，**落库越快越好**，否则数据比画面慢半拍。

高亮的收尾**不用 `Timer`**：`TweenAnimationBuilder` 播完自己停，切日期时清 `_flashKey`。
挂定时器清理会让 widget 测试报 `A Timer is still pending after the widget tree was disposed`。

### 4.4 列表差异：靠最长公共子序列决定谁动

`DayTimelineList` 里维护一份"当前显示的行"（`_rows`），数据一变就拿新列表跟它比：

1. 求新旧两个 key 序列的**最长公共子序列（LCS）**，落在里面的行位置没变，原地更新内容；
2. 其余的行（彻底消失的 + 跨区移动的）按索引从后往前 `removeItem`，播收拢；
3. 再按新顺序从头往后 `insertItem`，播展开。

⚠ **踩过的坑**：第一版只删"新列表里没有的 key"，跨区移动的行 key 在新列表里是存在的，
于是它既不被删、又不在原位，后面的贪心插入把同一行插成了两份
（真机/测试里都出现两个 `tile_task_2`）。**移动 ≠ 消失，必须一起进"重排"名单**。

为什么用 LCS 而不是"逐个比对位置"：分区标题、折叠条会随计数插入/移除，
用 LCS 能自动把这些连带变化收敛成"最少改动几条"，不会牵一发动全身。

### 4.5 数据库

`events.done` 从 V1 就有列，只是从来没有写入接口。本次只加了 `setEventDone`，**表结构没动、版本号没动**。

### 6.1 验收中抓到并修掉的缺陷：高亮色偏脏

**现象**：落位高亮本该是柔和的淡黄，真机上看到的是一块**脏灰褐色**。

**证据**：连拍第 2 帧该区域主色 `#C4C0B4`，而设计色是 `#FFF1C2`。

**原因**：

```dart
// 错
Color.lerp(const Color(0xFFFFF1C2), Colors.transparent, t)
```

`Colors.transparent` 是 `0x00000000` —— 透明**黑**，不是「淡黄的透明版」。`Color.lerp` 会把 RGB 一起拉向 0，t≈0.5 时得到半透明深褐 `(127,120,97,127)`，压在米黄底上正好是 `#C4C0B4`。

**修法**：

```dart
// 对：终点色是同色相的全透明版
Color.lerp(const Color(0xFFFFF1C2), const Color(0x00FFF1C2), t)
```

**回归**：`test/flash_highlight_test.dart` 断言中途帧的 RGB 必须仍是 `FFF1C2`（旧写法在 t=0.5 时红色分量是 0.5 而不是 1.0，第一条断言就会挂）。修完真机复测，高亮帧主色为 `#FFFAEB`（淡黄叠在米黄底上的正常渐隐），脏色消失。

### 6.2 第二轮验收：补位改成滑动（02:10–02:30）

用户反馈「消失后立刻补位，看起来好难受」，要求其它条目滑动到应有位置。
改成 `DayTimelineList` + AnimatedList 差异动画后重新验收，同一台机、11-22 那天：

| 观察点 | 结果 |

| 被勾那条在**原地**收拢（高度变小 + 变淡），不是瞬间消失 | 通过 |
| 同区其它条目**贴着收拢过程上滑**，位置连续变化（实测 y 约 190 → 130 → 110 → 55） | 通过 |
| 目标位置的卡片**从 0 展开**，把下面的条目往下推 | 通过 |
| 展开演完**之后**才亮高亮（而不是同时） | 通过 |
| 「已过期」变空时，段标题跟着收起消失 | 通过 |
