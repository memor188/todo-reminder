## 0. 开工前必读

### 0.1 硬性红线（违反会浪费几小时）

| 红线 | 原因 |
|---|---|
| 项目路径必须 `E:\todo-app`，**不能回到中文路径** | 中文路径让 Gradle daemon 用 GBK 解码 UTF-8 路径 → 无限死锁（已踩坑） |
| 所有依赖/缓存必须在 E 盘 | `GRADLE_USER_HOME=E:\AndroidDev\gradle-home`、`PUB_CACHE=E:\AndroidDev\pub-cache` 已设，别改 |
| 不装 Android Studio | 用 VS Code + 命令行 SDK |
| 代码交付前**必须真跑自检** | 编译过 ≠ 能用，要按每阶段验收清单逐条核对 |
| keystore 与密码绝不进 git | 丢失就无法更新已安装的 App |

### 0.2 环境自检（每次开工先跑一遍）

```bash
# 在 Git Bash 中执行
cd /e/todo-app/app
flutter --version          # 期望 Flutter 3.50.1 / Dart 3.14.0
java -version              # 期望 OpenJDK 17
adb devices                # 期望看到 iqoo z9 turbo 设备号（真机需 USB 调试已开）
echo $GRADLE_USER_HOME     # 期望 E:\AndroidDev\gradle-home
echo $PUB_CACHE            # 期望 E:\AndroidDev\pub-cache
```

若 `adb devices` 无设备：手机开「开发者选项 → USB 调试」，插线，弹窗点允许。

### 0.3 每阶段固定工作流

```
改代码 → flutter analyze → flutter build apk --debug → 真机 adb install → 照验收清单逐条测 → git commit 打节点
```

任何一步失败，**先快速重试一次**（用户规则：间歇拦截很常见），仍失败才排查，排查上限 6 轮工具调用、每轮换思路。

### 0.4 版本里程碑总览

| 阶段 | 目标 | 关键交付 | 前置 |
|---|---|---|---|
| **V0** | 验证通知链路能弹 | 输入框 + 时间选择器 + 到点通知 + 10 秒测试按钮 | 无 |

## 1. V0：验证通知链路（最先做）

### 1.1 范围

**做**：输入框（事项）、时间选择器、设置提醒按钮、10 秒测试按钮、到点弹通知、通知渠道、Android 13+ 权限申请。
**不做**：列表、存储、AI、后台保活、提前量、贪睡。

### 1.2 依赖版本（已查证 2026-11-21）

| 包 | 版本 | 说明 |
|---|---|---|
| `flutter_local_notifications` | `^23.0.3` | 23.0.3 发布于 2026-11-18；要求 Dart ^3.12、Flutter >=3.44（我们是 3.50.1/3.14.0，满足） |
| `timezone` | `^0.11.2` | FLN 23 依赖 `timezone ^0.11.0`，直接写 `^0.11.2` 即可，无冲突 |
| `material_ui` | **删除** | 模板残留，代码未使用 |

### 1.3 关键 API 签名（23.x 已变更，照旧教程写会报错）

```dart
// 1. 初始化：settings 是命名参数！旧版是位置参数
await flutterLocalNotificationsPlugin.initialize(
  settings: InitializationSettings(android: AndroidInitializationSettings('@mipmap/ic_launcher')),
  onDidReceiveNotificationResponse: (details) { /* 点击通知回 App */ },
);

// 2. 时区初始化（必须在 initialize 之前）
tz.initializeTimeZones();

// 3. Android 13+ 权限（在 main 里请求）
await flutterLocalNotificationsPlugin
    .resolvePlatformSpecificImplementation<AndroidFlutterLocalNotificationsPlugin>()
    ?.requestNotificationsPermission();

// 4. 精确闹钟权限（Android 12+，用 SCHEDULE_EXACT_ALARM 时）
await flutterLocalNotificationsPlugin
    .resolvePlatformSpecificImplementation<AndroidFlutterLocalNotificationsPlugin>()
    ?.requestExactAlarmsPermission();

// 5. 定时调度：androidScheduleMode 必填！旧版是 androidAllowWhileIdle 布尔值
await flutterLocalNotificationsPlugin.zonedSchedule(
  id,
  title,
  body,
  tz.TZDateTime.from(eventTime, tz.local),
  NotificationDetails(
    android: AndroidNotificationDetails(
      channelId, channelName,
      channelDescription: '待办提醒',
      importance: Importance.high,
      priority: Priority.high,
    ),
  ),
  androidScheduleMode: AndroidScheduleMode.exactAllowWhileIdle,
  uiLocalNotificationDateInterpretation:
      UILocalNotificationDateInterpretation.absoluteTime,
);
```

**通知渠道说明**：FLN 23 在 `show/zonedSchedule` 时若 channel 不存在会**自动创建**（按 `AndroidNotificationDetails` 里指定的 id/name/importance）。V0 用 `AndroidNotificationDetails` 即可，不必单独调 `createNotificationChannel`。channel id 定为常量 `todo_reminders`，**以后不许改**（改了旧通知的设置全丢）。

### 1.4 AndroidManifest.xml 改动

路径：`app/android/app/src/main/AndroidManifest.xml`，在 `<manifest>` 下、`application` 前加：

```xml
<uses-permission android:name="android.permission.POST_NOTIFICATIONS"/>
<uses-permission android:name="android.permission.SCHEDULE_EXACT_ALARM"/>
<uses-permission android:name="android.permission.RECEIVE_BOOT_COMPLETED"/>
```

> 选 `SCHEDULE_EXACT_ALARM` 而非 `USE_EXACT_ALARM`：后者是给闹钟/日历类 App 的，Google Play 审核会限制用途；我们自用+分发，前者配 `requestExactAlarmsPermission()` 更合适。

### 1.6 实施步骤（按顺序执行）

1. **改 pubspec.yaml** → 运行 `flutter pub get`（观察是否全从 E 盘缓存取）。
2. **改 AndroidManifest.xml** 加三条权限。
3. **新建 notification_service.dart**：照 1.3 写单例，4 个方法。写完后单独 inspect 一遍 import 是否齐全。
4. **重写 main.dart**：
   - `main()` 改 `async`，首行 `WidgetsFlutterBinding.ensureInitialized()`；
   - 依次 `tz.initializeTimeZones()` → service.init() → service.requestPermission()；

   - 点设置提醒 → 取当前日期 + 选定时分 → 调 `schedule()`；
   - 点 10 秒测试 → `DateTime.now().add(10s)` → 调同样的 `schedule()`。
5. **处理 test/widget_test.dart**：删掉模板里的计数器测试。
6. **自检第一关**：`flutter analyze` → 期望 `No issues found`，退出码 0。
7. **自检第二关**：`flutter build apk --debug` → 退出码 0，产出 `build/app/outputs/flutter-apk/app-debug.apk`。上次迁移后此步耗时约 7 分钟，属正常。
8. **真机验收**：`adb install -r build/app/outputs/flutter-apk/app-debug.apk`，按 1.7 清单逐条测。
9. **打 git 节点**：`git add -A && git commit -m "V0: 通知链路验证通过"`。

### 2.3 数据库设计（三张表，分别建）

```sql
-- courses 课程（改一次=改整学期）
CREATE TABLE courses(
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  title TEXT NOT NULL,
  day_of_week INTEGER NOT NULL,   -- 1=周一 ... 7=周日
  start_time TEXT NOT NULL,       -- '08:00'
  end_time TEXT NOT NULL,         -- '09:40'
  location TEXT,
  color TEXT,
  semester_start TEXT NOT NULL,   -- ISO 日期
  semester_end   TEXT NOT NULL
);

-- events 事件型待办（绝对时刻，到点必须在那）
CREATE TABLE events(
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  title TEXT NOT NULL,
  start_at TEXT NOT NULL,         -- ISO 8601 绝对时间
  location TEXT,
  note TEXT,
  done INTEGER NOT NULL DEFAULT 0
);

-- tasks 任务型待办（当天做完即可，时刻可空）
CREATE TABLE tasks(
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  title TEXT NOT NULL,
  due_date TEXT NOT NULL,         -- ISO 日期
  due_time TEXT,                  -- 可空
  location TEXT,
  note TEXT,
  done INTEGER NOT NULL DEFAULT 0
);
```

### 2.6 备份恢复的实现要点（2026-11-21 用户拍板，定稿）

- **导出（A 轴定稿：默认不含 key）**：读三张表 → 组装 JSON → 用 `path_provider` 写到 Download → 文件名带 schema 版本。**API key 不进备份**；另做高级选项「包含配置」（默认关），勾选时才把 shared_preferences 的配置一起写入，并弹明文警示。
- **导入（B 轴定稿：覆盖式）**：文件选择器选 JSON → 校验版本 → 二次确认弹窗"将覆盖当前所有数据" → 数据库事务内清空三张表 + 写入 → 失败整体回滚。
- 不做合并去重、增量恢复、跨版本迁移。
- **A、B 是两个独立轴，不是二选一**：各选一个组成策略，本项目选「不含 key + 覆盖式」。

### 2.8 release 签名打包（V1 末尾做，一次搞定）

1. 生成 keystore（**放 E 盘项目外的安全位置，绝不进 git**）：
   ```bash
   keytool -genkey -v -keystore E:/AndroidDev/keystores/todo-app.jks \
     -keyalg RSA -keysize 2048 -validity 10000 -alias todo
   ```
2. 在项目根建 `android/key.properties`（**加入 .gitignore**），写 storeFile / storePassword / keyPassword / keyAlias。
3. 改 `android/app/build.gradle.kts`：读 key.properties，配置 `signingConfigs { create("release") { ... } }`，在 `buildTypes.release` 里 `signingConfig = signingConfigs.getByName("release")`。
4. 加 `.gitignore`：`android/key.properties`、`*.jks`、`*.keystore`。
5. 验证 `git status` 里看不到 keystore 和 key.properties。
6. **单独备份 keystore 到另一个物理位置**（U 盘/网盘），并告诉用户密码保管位置——丢了就无法更新已安装的 App。

## 3. V2：差异化核心 + 硬提醒

### 3.1 范围

**做**：课表周网格、AI 对话录入（草稿卡片）、硬提醒（响铃震动）、ROM 白名单指引、单双周规则。
**不做**：课程导入（V3）、重复规则、优先级标签。

### 3.2 依赖（在 V1 基础上加）

```yaml
http: ^1.x               # 调 DeepSeek OpenAI 兼容接口
device_info_plus: ^x     # 检测 ROM 类型，弹对应白名单引导（可选，见需求 E.3）
```

### 3.3 实施步骤

1. **AI 模块**（先做，因为课表不依赖它）：
   - 设置页已有 baseURL/apiKey/model → 新建 `services/ai_service.dart`；
   - POST 到 `{baseURL}/v1/chat/completions`，Header 带 `Authorization: Bearer {apiKey}`；
   - **prompt 必须注入当前日期**：`"今天是 ${DateTime.now()} 星期X"`（需求第十一节第 1 条）；
   - 要求模型返回 JSON（JSON mode / function calling），字段映射三类条目；
   - 草稿卡片常驻：AI 每次返回增量更新卡片，字段可点开改；
   - 用户确认 → 写入对应表（V2 仍只新建，不改已有）；
   - 用规格里两个真实样例测：「周五17点E栋104考试」「12.03E栋103听讲座」。
2. **课表网格 tab**：把占位换成实际 7 列 × 时间轴，课程就地渲染周期块（不需要展开），事件/任务同网格不同画法（浅色实心/强色实心/白底虚线）。两视图共用 `db_service` 的数据。
3. **硬提醒四关**（按此顺序攻，一次一关）：
   - 通知渠道：V0 已建（channel id 不变）；
   - Doze：用 `zonedSchedule` 的 `exactAllowWhileIdle`（V0 已用）；
   - **开机重注册**：监听 `RECEIVE_BOOT_COMPLETED` 广播，重启后重新注册所有未到期提醒（V0 已加权限，这里实现 receiver）；
   - **国产 ROM 白名单**：在「我的」页放机型适配指引，至少覆盖 OriginOS（路径见需求附录 E.2）、MIUI、EMUI；可选 `device_info_plus` 检测 ROM 弹对应引导。
4. **单双周规则**：courses 表加 `week_parity` 字段（0=每周/1=单周/2=双周），展开逻辑按学期周数过滤。
5. 自检 → 真机验收（关键：**锁屏 + 划走 App 后**提醒是否还准时，这是 V2 的核心验证）。
6. git 节点 + tag `v1-done`。

### 3.4 V2 验收要点

- [ ] AI 输入两个真实样例 → 草稿卡片解析出正确的事件型条目（类型/时间/地点）
- [ ] 草稿字段可点开修改 → 确认后入库正确
- [ ] 课表网格显示课程块，与日程列表数据一致
