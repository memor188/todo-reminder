## 0. 开工前必读

### 0.1 硬性红线（违反会浪费几小时）

| 红线 | 原因 |
|---|---|
| 项目路径必须 `E:\todo-app`，**不能回到中文路径** | 中文路径让 Gradle daemon 用 GBK 解码 UTF-8 路径 → 无限死锁（已踩坑） |

| 不装 Android Studio | 用 VS Code + 命令行 SDK |
| 代码交付前**必须真跑自检** | 编译过 ≠ 能用，要按每阶段验收清单逐条核对 |
| keystore 与密码绝不进 git | 丢失就无法更新已安装的 App |

### 1.3 关键 API 签名（2026-11-21 实战修正，以本地安装版为准）

> **重要教训**：GitHub master 分支的 README 与实际发布的 23.0.3 **不一致**（README 更新）。
> 唯一可靠来源是本地缓存 `E:\AndroidDev\pub-cache\hosted\pub.dev\flutter_local_notifications-23.0.3\lib\src\flutter_local_notifications_plugin.dart`
> 和 `platform_flutter_local_notifications.dart`。写代码前 grep 这两个文件的签名，别信任何教程（包括本文档旧版）。

```dart
import 'package:timezone/data/latest.dart' as tzdata;  // 0.11.x：initializeTimeZones 在这里，不在 timezone.dart
import 'package:timezone/timezone.dart' as tz;

// 1. 时区初始化（必须在 initialize 之前）
tzdata.initializeTimeZones();

// 2. 初始化：settings 是命名参数
await flutterLocalNotificationsPlugin.initialize(
  settings: InitializationSettings(
    android: AndroidInitializationSettings('@mipmap/ic_launcher'),
  ),
  onDidReceiveNotificationResponse: (response) { /* 点击通知回 App */ },
);

// 3. Android 13+ 通知权限 / 12+ 精确闹钟权限（在 main 里请求）
await flutterLocalNotificationsPlugin
    .resolvePlatformSpecificImplementation<AndroidFlutterLocalNotificationsPlugin>()
    ?.requestNotificationsPermission();
await flutterLocalNotificationsPlugin
    .resolvePlatformSpecificImplementation<AndroidFlutterLocalNotificationsPlugin>()
    ?.requestExactAlarmsPermission();

// 4. 定时调度：23.0.3 顶层入口是【全命名参数】
//    注意：uiLocalNotificationDateInterpretation 在 23.x 已移除，别写！
await flutterLocalNotificationsPlugin.zonedSchedule(
  id: id,
  title: title,
  body: body,
  scheduledDate: tz.TZDateTime.from(eventTime, tz.local),
  notificationDetails: notificationDetails, // NotificationDetails 类型
  androidScheduleMode: AndroidScheduleMode.exactAllowWhileIdle, // 必填
);

// 5. 取消：id 也是命名参数
await flutterLocalNotificationsPlugin.cancel(id: id);
```

**实战踩坑记录**（`flutter analyze` 抓到并已修复）：
- `tz.initializeTimeZones()` 未定义 → 改为 `tzdata.initializeTimeZones()`（导入 `timezone/data/latest.dart`）。
- `zonedSchedule` 用位置参数 → 全部改命名参数。
- `uiLocalNotificationDateInterpretation` 未定义 → 23.x 已移除，直接删掉。
- `cancel(id)` 位置参数 → 改 `cancel(id: id)`。

**通知渠道说明**：FLN 23 在 `show/zonedSchedule` 时若 channel 不存在会**自动创建**（按 `AndroidNotificationDetails` 里指定的 id/name/importance）。不必单独调 `createNotificationChannel`。channel id 定为常量 `todo_reminders`，**以后不许改**（改了旧通知的设置全丢）。

### 1.3a Flutter engine jar 下载慢（2026-11-21 实战坑）

现象：`flutter build apk` 卡在 `Running Gradle task 'assembleDebug'...` 几十分钟不动。
根因：Gradle info 日志显示卡在从 `storage.googleapis.com/download.flutter.io` 下载 Flutter engine 的 native jar（arm64/x86_64/armeabi_v7a 三个，每个约 190MB）。Flutter 升级后 engine hash 变化，旧缓存作废需重下，而 Google 系域名在本机被限速到 ~60KB/s。

**解法**（构建命令固定这么写）：
```bash
FLUTTER_STORAGE_BASE_URL=https://storage.flutter-io.cn \
  flutter build apk --debug --target-platform android-arm64
```
- 国内镜像 `storage.flutter-io.cn` 实测 ~311KB/s，是 Google 源的 5 倍。
- `--target-platform android-arm64` 只下一个架构的 engine jar（我们只在 iQOO Z9 Turbo 真机测试），省 2/3 下载量。
- **判活技巧**：卡住时看 `E:\AndroidDev\gradle-home\.tmp\gradle_download*.bin` 是否在增长、java 进程 CPU 是否 >10 秒；两者都在动 = 在下载不是死锁。用 `./gradlew assembleDebug --info` 能看到具体下载 URL。

### 1.3b compileSdk 必须升到 37（2026-11-21 实战坑）

`flutter_local_notifications 23.x` 要求 **compileSdk >= 37**，而 Flutter 模板默认 `compileSdk = flutter.compileSdkVersion`（36）。不升会先警告、再导致构建长时间卡在 Gradle 任务上（实测误判为网络慢，实际是版本不匹配 + 反复尝试）。

修复：在 `android/app/build.gradle.kts` 把 `compileSdk = flutter.compileSdkVersion` 改为 `compileSdk = 37`。本机 `E:\AndroidDev\android-sdk\platforms\android-37.0` 已安装，无需再下。

### 1.3c core library desugaring（2026-11-21 实战坑）

报错：`Dependency ':flutter_local_notifications' requires core library desugaring to be enabled for :app.`
修复（`android/app/build.gradle.kts`）：
```kotlin
android {
    compileOptions {
        isCoreLibraryDesugaringEnabled = true   // 加这行
    }
}
dependencies {
    coreLibraryDesugaring("com.android.tools:desugar_jdk_libs:2.1.4")
}
```

### 1.4 AndroidManifest.xml 改动

路径：`app/android/app/src/main/AndroidManifest.xml`，在 `<manifest>` 下、`application` 前加：

```xml
<uses-permission android:name="android.permission.POST_NOTIFICATIONS"/>
<uses-permission android:name="android.permission.SCHEDULE_EXACT_ALARM"/>
<uses-permission android:name="android.permission.RECEIVE_BOOT_COMPLETED"/>
```

> 选 `SCHEDULE_EXACT_ALARM` 而非 `USE_EXACT_ALARM`：后者是给闹钟/日历类 App 的，Google Play 审核会限制用途；我们自用+分发，前者配 `requestExactAlarmsPermission()` 更合适。

**还必须在 `<application>` 内声明插件的 receiver（2026-11-21 真机踩坑）**：FLN 从 v16 起不再在自己的 Manifest 里声明它们。只加权限不声明 receiver 时，闹钟会照常触发（logcat/alarms 看得到），但广播无人接收，通知**永远不会出现**——极易误判为权限或时区问题。

```xml
<receiver android:exported="false"
    android:name="com.dexterous.flutterlocalnotifications.ScheduledNotificationReceiver" />
<receiver android:exported="false"
    android:name="com.dexterous.flutterlocalnotifications.ScheduledNotificationBootReceiver">
    <intent-filter>
        <action android:name="android.intent.action.BOOT_COMPLETED"/>
        <action android:name="android.intent.action.MY_PACKAGE_REPLACED"/>
        <action android:name="android.intent.action.QUICKBOOT_POWERON" />
        <action android:name="com.htc.intent.action.QUICKBOOT_POWERON"/>
    </intent-filter>
</receiver>
```

自检命令：`adb shell dumpsys package com.anlu.todo_app | grep ScheduledNotificationReceiver`，**必须有输出**才算装对。

### 2.3 数据库设计（三张表，分别建）

```sql
-- courses 课程（改一次=改整学期）
CREATE TABLE courses(
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  title TEXT NOT NULL,
  day_of_week INTEGER NOT NULL,   -- 1=周一 ... 7=周日
  start_time TEXT NOT NULL,       -- '08:00'
  end_time TEXT NOT NULL,         -- '09:40'
  location TEXT,
  color TEXT,
  semester_start TEXT NOT NULL,   -- ISO 日期
  semester_end   TEXT NOT NULL
);

-- events 事件型待办（绝对时刻，到点必须在那）
CREATE TABLE events(
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  title TEXT NOT NULL,
  start_at TEXT NOT NULL,         -- ISO 8601 绝对时间
  location TEXT,
  note TEXT,
  done INTEGER NOT NULL DEFAULT 0
);

-- tasks 任务型待办（当天做完即可，时刻可空）
CREATE TABLE tasks(
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  title TEXT NOT NULL,
  due_date TEXT NOT NULL,         -- ISO 日期
  due_time TEXT,                  -- 可空
  location TEXT,
  note TEXT,
  done INTEGER NOT NULL DEFAULT 0
);
```

#### 2.8.1 release 构建的两个坑（2026-11-22 修）

**坑 1：`exclusiveContent` 放在 `:app` 里不够。**

现象：`./gradlew assembleRelease` 报

```
Could not resolve io.flutter:flutter_embedding_release:1.0.0-4d357...
  Required by: project ':android_file_picker'
  > Could not get resource 'https://storage.googleapis.com/download.flutter.io/...pom'
```

原因：`repositories {}` 只作用于声明它的那个工程。插件子工程（`android_file_picker` / `sqflite_android` / `shared_preferences_android` / `flutter_local_notifications`）也会解析 `io.flutter:flutter_embedding_<variant>`，它们各自带一份网络仓库。debug 之所以没暴露问题，是因为当时这些包早已躺在 Gradle 缓存里；换成 release 才第一次真正去解析。

修法：把 `exclusiveContent` 上移到**根工程** `android/build.gradle.kts`：

```kotlin
allprojects {
    repositories {
        exclusiveContent {
            forRepository { maven { url = uri("file:///E:/AndroidDev/local-maven") } }
            filter { includeGroup("io.flutter") }
        }
        // ……原有的 aliyun / google / mavenCentral
    }
}
```

`app/build.gradle.kts` 里那段相应删掉，只用注释指回根配置，避免两处各改一半。

**坑 2：`assembleRelease` 不能带 `--offline`。**

本地 maven 仓库里 release 的包是新手工拷进去的（`arm64_v8a_release`、`flutter_embedding_release`），Gradle 的 `module-artifact.bin` 索引里没有登记。`--offline` 模式下 Gradle 拒绝任何未登记的解析，直接报 `No cached version of io.flutter:flutter_embedding_release available for offline mode`。

但**别加 `--offline` 也不会联网**：`io.flutter` 被 `exclusiveContent` 独占锁在 `file://` 仓库，解析纯磁盘操作。其余依赖版本都是固定的，命中缓存即可，不会去 aliyun/central 拉。

> 反例提醒：不要试图清空 `module-artifact.bin` 来"刷新索引"。2026-11-21 试过一次，直接把全部依赖索引（含 Kotlin 插件）搞丢，debug 也构建不了。

**另外：`-Ptarget-platform=android-arm64` 必须带。** Flutter Gradle 插件默认要 `android-arm,android-arm64,android-x64` 三个 ABI，而本地仓库里只有 `arm64_v8a_release`（`armeabi_v7a_release`、`x86_64_release` 从未下载过）。不带这个参数就会去要缺失的包。

**实测结果（2026-11-22）**：`BUILD SUCCESSFUL in 2m 2s`，APK 19,826,687 字节（18.9 MB），签名 DN `CN=AnLu Todo`（自建 key，非 debug 证书），内含 `lib/arm64-v8a/libapp.so` 6.3 MB（AOT 快照）+ `libflutter.so` 11.3 MB，无 `kernel_blob.bin`。改完根配置后 debug 复验 `assembleDebug --offline` 仍 `BUILD SUCCESSFUL in 1m 12s`。

### 3.6 V2 实施记录与踩坑（2026-11-21）

**依赖**：`http`（AI 调用）。不需要 `device_info_plus`——白名单改用静态折叠指引，先不做 ROM 自动检测。

**踩坑**：

1. **`am force-stop` 会取消 PendingIntent**：`dumpsys alarm` 里出现 `Reason=pi_cancelled`，看起来"到点不响"，其实是测试手法把闹钟废了。验后台提醒统一用 `am kill`（只杀进程，保留 PendingIntent）。

8. **Gradle artifact 索引被强杀写坏，导致"构建卡死"**：`flutter build apk` 连续两次静默 `SIGTERM`，`dart`/`java` 进程 CPU 全为 0。定位过程：`gradlew assembleDebug --offline` 单独跑 32 秒就报错，说明不是编译慢，而是 `:app:compileDebugKotlin` 解析 `io.flutter:armeabi_v7a_debug` 失败——`No cached version available for offline mode`。**文件其实都在** `caches/modules-2/files-2.1/io.flutter/` 里，坏的是 `metadata-2.107/module-artifact.bin`（此前进程被杀时写坏的索引）。不加 `--offline` 时 Gradle 会去 `storage.googleapis.com/download.flutter.io` 重下 427MB，而该源实测只有 **约 40KB/s**（60 秒只下 2.4MB），于是前台等到超时被 SIGTERM，表现为"卡住没输出"。
   **错误尝试**：删掉 `module-artifact.bin` 会让 Gradle 丢掉**全部**依赖索引，连 Kotlin 插件都要重下（`--offline` 直接全线报错）。**必须整目录备份再动**（`cp -r metadata-2.107 metadata-2.107.bak`）。
   **最终方案**：在 `E:\AndroidDev\local-maven` 搭本地离线 maven 仓库，并用 `exclusiveContent` 把 `io.flutter` 这一组独占锁到本地：
   ```kotlin
   repositories {
       exclusiveContent {
           forRepository { maven { url = uri("file:///E:/AndroidDev/local-maven") } }
           filter { includeGroup("io.flutter") }
       }
   }
   ```
   ⚠️ **jar 必须只含 `lib/*.so`**：SDK 自带的 `bin/cache/artifacts/engine/android-arm/flutter.jar` 里**含 embedding 的 class**，直接拿来当 `armeabi_v7a_debug` 会触发 `checkDebugDuplicateClasses`（与 `flutter_embedding_debug` 重复）。正确做法是取 Gradle 缓存里那份只含 `lib/armeabi-v7a/libflutter.so` 的 jar（`unzip -l` 应为 1 个 entry、0 个 `.class`）。改完后离线构建 **1 分 8 秒**通过。
9. **`adb install` 报 `User rejected permissions` 不一定是用户拒绝**：查 `dumpsys window | grep mDreamingLockscreen` 为 `true`（屏幕锁着），vivo 的安装确认框弹不出来就自动判失败。**解锁屏幕后一次装好**。
10. **`adb shell uiautomator dump /sdcard/ui.xml` 在 Git Bash 下会被路径转义成 Windows 路径**（`E:/workbuddy/.../sdcard/ui.xml`），必须先 `export MSYS_NO_PATHCONV=1`。Flutter 页面的文本在 `content-desc` 而不是 `text` 里，且只有被系统询问无障碍时才填充语义树——拿它做点击坐标比按截图估算可靠得多（本轮按截图估算曾偏 18px 导致点了三次没反应）。

### 3.8 输入体验：掩码输入 + 学期方案（2026-11-21）

用户提了两条使用痛点，讨论后拍板：

**需求**

1. **日期和时间的分隔符固定，只敲数字**。现在 `2026-11-21`、`08:00` 的横杠冒号都要手打，label 上还写着格式提示。
2. **学期起止做成可复用方案**。学期每学期只变一次，却每次新建课程都要重打；建一套「2026秋」，以后一键套用。

用户对三个待定点的拍板：输入方式「按建议来」（自动补分隔符）；方案管理放「我的」页集中管理；新建课程时**当前日期落在哪段学期就自动选哪个**。

**实现**

| 模块 | 说明 |
|---|---|
| `widgets/masked_formatters.dart` | `DateMaskFormatter` / `TimeMaskFormatter`：剥掉非数字 → 按位插分隔符。`20261121` → `2026-11-21`，`0800` → `08:00`；粘贴带分隔符的完整值也能识别；全角数字先归一化再处理 |
| 同上（退格） | 退格落在分隔符上时新文本只少了个 `-`、数字一个没少。若不管，用户会觉得「退格没反应」。做法是检测到这种情况主动多删一位数字 |
| `models/semester_plan.dart` | `SemesterPlan{id,name,start,end}` + `contains()` + `pickForDate()`：按天比较、含首尾；重叠时取开始日更晚的（范围更窄，通常才是用户此刻真实在上的学期） |
| `services/settings_service.dart` | 方案列表存 SharedPreferences（JSON），与 AI 配置同一处；解析失败按空处理，不让一条脏数据拖垮录入页 |
| `screens/semester_plans_screen.dart` | 「我的」页 → 「学期方案」：列表 + 新增/编辑/删除。校验名称非空、日期 8 位可解析、结束不早于开始 |
| `screens/manual_input_screen.dart` | 五个日期/时间框全部挂掩码 formatter；课程类型多一个「学期方案」下拉，选中即填起止；切到「课程」时按当前日期自动预选一次（只预选一次，避免覆盖用户手改过的值）；编辑已有课程时若学期起止与某方案完全一致则选中它 |

**关键取舍**

- 掩码输入的光标固定跳到末尾。8 位数字的输入几乎不会回去改中间某位，换来的是实现简单、不会有光标卡在分隔符上的怪状态。
- 「自动预选」只在切到课程类型那一刻做一次判断。用户之后手动改学期日期，再切走切回不会被静默覆盖——这属于「不能替用户悄悄改数据」的底线。
- 学期起止不是摆设：单双周靠 `day.difference(semesterStart).inDays ~/ 7 + 1` 算第几周，套错方案会让整门课排到错误的周。所以下拉里不只显示方案名，还带上实际起止日期供核对。

**测试**

新增 `test/masked_formatters_test.dart`（11 个：补分隔符、全角、粘贴、截断、退格、清空）与 `test/semester_plan_test.dart`（14 个：首尾含入、忽略钟点、越界、重叠取窄、序列化容错），`widget_test.dart` 加 2 个（我的页新增方案、新建课程自动预选）。测试总数 **50 → 75**，`flutter analyze` 0 问题。

## 附录：把仓库推到 GitHub（2026-11-22）

### 结论先说：只有 API 能走

| 通道 | 实测结果 |
|---|---|
| `git push` 到 github.com | **不通**。`curl https://github.com` 返回 000、15 秒超时；`git push` 报 `CONNECT tunnel failed, response 502` |
| `api.github.com` | **通**。返回 200，约 1.8 秒 |
| WorkBuddy 的 GitHub connector | 只能读。`get_me` 正常，`create_repository` 返回 `403 Resource not accessible by integration` |

所以**配 SSH key 也没用**，git 协议这条域名就过不去。所有 GitHub 操作必须走 REST API。

### 上传方式：Git Data API 逐提交重建

用 `tools/push_to_github.py`，不是 `git push`：

1. 建仓库（`POST /user/repos`）
2. 遍历本地 `git log --reverse`，对每个提交：
   - `POST /git/trees` —— 文件列表，文本走内联 `content`，二进制（png）先 `POST /git/blobs` 拿 sha（同一 blob 缓存复用，否则同一张图标会被传 18 次）
   - `POST /git/commits` —— 带上原始 author/committer 的 name/email/date
3. `PATCH /git/refs/heads/main` 指向最后一个提交
4. 注解 tag 先 `POST /git/tags` 建 tag 对象，再挂 ref

### 踩过的四个坑

1. **空仓库不能建 tree**：`POST /git/trees` 返回 `409 Git Repository is empty`。必须先 `PUT /contents/.bootstrap` 塞个占位提交，把仓库变成非空。占位提交最后会悬空（main 指向重建的第一个提交）。
2. **空仓库查 ref 返回 409 而不是 404**：`GET /git/ref/heads/main` 在空仓库上是 409，判断"还没有分支"时两个码都要当缺省处理。
3. **blob 路径漏了前缀**：`POST /git/blobs` 不行，要 `/repos/{owner}/{repo}/git/blobs`。这个 bug 前 4 个提交都发现不了（那时还没有二进制文件），到第 5 个（初始化 Flutter 项目、带 png 图标）才炸。
4. **注解 tag 的 `%(objectname)` 是 tag 对象自身的 sha**，不是它指向的提交。`git for-each-ref` 要用 `%(*objectname)` 解引用，不然在本地→远端 sha 映射表里查不到，tag 会被静默跳过。

另一个容易踩的：**历史被 `filter-branch` 重写后，本地和远端的同名提交 sha 完全不同**。所有查作者、查 tag message 的操作都要用本地 sha，远端 sha 只能喂给 API。写反了会报 `git log ... returned non-zero exit status 128`。

### 校验

推完不能只看 HTTP 200。用 tree sha 比对——tree 的 sha 由文件内容和路径决定，两边一致就等于逐字节相同：

```
本地 HEAD tree:  0f68eefca63abcb1a60ae07c94c43f48f3f8d9ea
远端 HEAD tree:  0f68eefca63abcb1a60ae07c94c43f48f3f8d9ea
```

18 个提交逐个比对，**全部一致**；远端 tag 三个齐全；提交时间保留原值（`2026-11-22T04:23:58Z` = 本地 `12:23:58 +08:00`）。
