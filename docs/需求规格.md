# 待办 App 需求规格 v0.9

> 状态：**讨论中，未定稿**。带 `??` 的是待定项。
> 最后更新：2026-10-27

---

## 一、定位

一个**安卓手机上的待办 App**，核心是"到规定时间提醒我要做什么"。

不做多人协作、不做云同步（V1）、不做账号系统。就用它自己。

---

## 二、已定稿

### 平台与技术栈

| 项 | 决定 |
|---|---|
| 平台 | 安卓（用户主力机） |
| 框架 | **Flutter**（Dart），VS Code + 命令行 Android SDK |
| 环境 | SDK 全部装 E 盘，**不装 Android Studio** |
| 存储 | V1 用本地轻量方案（数据量小，几百条级别） |
| 界面风格 | 参考：**周视图网格**（左侧时间轴 + 顶部日期条 + 彩色色块按时间段铺开，一目了然）；配色简约 ?? |

### 提醒

| 决策点 | 决定 |
|---|---|
| 终态目标 | **硬提醒**：到点响铃 + 震动，不点"完成"不消失 |
| V1 实现 | 先做**软提醒**（通知栏一条），跑通链路后再升硬提醒 |
| 提前量 | V1 只做"到点"，不做提前提醒 |
| 重复 | V1 只做一次性 |
| 贪睡（稍后再提醒） | V2 |
| 未处理的通知 | 常驻，不可滑动清除 |

硬提醒需过的关（V2）：Doze 省电模式、国产 ROM 电池优化白名单、开机后重新注册闹钟、Android 8+ 通知渠道。

### 待办字段

| 字段 | V1 |
|---|---|
| 事项（一句话标题） | ✅ 必填 |
| 时间 | ✅ 必填 |
| 备注 | ⚪ 可选（一行） |
| 完成打勾 | ✅ |
| 过期未做 | 标红留在「逾期」区，**不自动顺延** |
| 优先级 / 标签 / 分类 | ❌ V2 |

### 录入方式一：手动

点 `+` → 选"自己填" → 填事项 + 选时间 → 保存。

### 录入方式二：AI 对话

- 入口：点 `+` → 选"问 AI"
- 交互：**草稿卡片常驻**在对话旁，每轮对话后增量更新，用户随时点确认（替代"AI 判定信息充分才出草稿"）
- 确认后：进待办列表
- 不同意：继续讨论
- 也可以**在草稿上直接改**再入库（卡片每个字段可点开编辑）
- 信息不全：AI 追问一句，不自己瞎填
- 时间解析：由模型输出**绝对时间戳**（ISO），App 只做校验
- V1 边界：只能**新建**待办，不能改已有的 ??

## 三、待定项 ??

3. **主视图形态**：周网格视图（像课程表）vs 列表为主+周历条——已给用户对比，待拍板。
4. **AI 第一句谁先说**：用户开口 vs AI 主动问"什么事？什么时候？"

| 版本 | 范围 |
|---|---|
| **V0** | 输入框 + 时间选择器 + 到点真的弹通知。**无列表、无存储、无 AI** ——只为验证提醒链路 |
| **V1** | + 待办列表 + 完成打勾 + 本地存储（重启不丢）+ 手动录入 |

## 五、技术要点备忘

1. **相对时间解析**：必须在发给模型的请求里注入"今天是 YYYY-MM-DD 星期X"，否则模型无法正确理解"后天""下周三"。
2. **结构化输出**：让模型返回 JSON（用 JSON mode / function calling），App 直接解析成草稿卡片，不要让它返回自由文本再正则硬拆。
3. **API key 安全**：
   - 不写死在代码里、不提交进 git
   - Flutter App 可被反编译，客户端存 key 有泄露风险 → 设额度上限、用便宜模型
   - V1 单人自用可接受，若日后分发需改走后端代理
4. **提醒可靠性**（V2 硬提醒的四个坑）：Doze、电池优化白名单、开机重注册、通知渠道。
5. **环境问题**：Java 未安装（Flutter 安卓编译需 JDK 17）；本机 GitHub 不通，参考项目走 Gitee 或由我读取源码片段。
