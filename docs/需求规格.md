# 待办 App 需求规格 v1.0

> 状态：**需求定稿，可开工**（2026-11-21）
> 剩余问题见第八节，不影响 V0/V1 动工。

---

## 一、定位

一个**安卓手机上的日程待办 App**，核心是"到规定时间提醒我要做什么"。

用户明确的原动力：现有课程表 App 有日程功能，但**没有 AI 对话录入**。

不做多人协作、不做账号系统、V1 不做云同步。自用。

---

## 二、平台与技术栈

| 项 | 决定 |
|---|---|
| 平台 | 安卓（用户主力机） |
| 框架 | **Flutter**（Dart），VS Code + 命令行 Android SDK |
| 环境 | SDK 全部装 **E 盘**，**不装 Android Studio** |
| 存储 | V1 本地轻量方案（几百条级别，不上数据库） |
| 界面风格 | 简约：白底、主题蓝、圆角卡片、清晰层级 |
| AI 供应商 | **DeepSeek**，但做成**可配置**：baseURL + apiKey + model，走 OpenAI 兼容 `/v1/chat/completions` |

---

## 三、数据模型：三类条目，一套视图

| 类型 | 特征 | 时间形态 | 完成 |
|---|---|---|---|
| **课程** | 周期规则（每周X / 单双周）+ 地点 + 颜色 | 时间块（08:00-09:40） | 不打勾，随学期 |
| **事件型待办** | 考试、讲座、开会——到点必须在那 | 绝对时间点 | 过了就没了 |
| **任务型待办** | 写作业、取快递——当天做完即可 | 日期（时刻可空） | 打勾后消失 |

**关键：数据层分三类独立管理，显示层混排。** 不要为了混排把三者塞进同一个结构——课程的"改一次 = 改整学期"和待办"就改这一次"语义完全不同。

---

## 四、界面

### V1 主视图：日程列表（用户 2026-11-21 拍板）

- 顶部：日期标题 + 7 日历条（有课的日子标圆点）
- 主体：按日期分组的时间线，三类条目混排
  - 课程：灰蓝底 + 「课」标签
  - 事件：左侧强色条（红/橙）
  - 任务：虚线圈 + 圆形勾选框
- 底部导航：`日程` / `课表` / `我的`

### V2 加：课表 tab = 周网格视图

- 左侧时间轴 + 7 列网格，课程与事件、任务同网格铺开
- 三种块三种画法：课程浅色实心、事件强色实心、任务白底虚线

> 两视图共用同一份数据。课程在网格里是"就地渲染"，在列表里需先把周期规则**展开成具体日期**再排序。

## 五、提醒

| 决策点 | 决定 |
|---|---|
| 终态目标 | **硬提醒**：到点响铃 + 震动，不点不掉 |
| V1 | 先做**软提醒**（通知栏一条） |
| 提前量 | V1 只做"到点" |
| 贪睡 | V2 |
| 未处理通知 | 常驻不消失 |
| 事件 vs 任务 | **提醒策略应不同**：事件到点硬提；任务当天提一次（延后细调） |

硬提醒四关（V2）：Doze 省电、国产 ROM 电池白名单、开机重注册闹钟、Android 8+ 通知渠道。

## 六、录入

### 方式一：手动
点 `+` → 自己填 → 事项 + 时间 + 地点 → 保存。

### 方式二：AI 对话（本项目的差异化核心）
- 点 `+` → 问 AI
- **草稿卡片常驻**，每轮对话后增量更新，用户随时确认
- 卡片字段可逐个点开修改后再入库
- 信息不全：AI 追问，不瞎填；也允许**留空标"待补"**（地点尤其常见）
- 时间解析：模型输出 **ISO 绝对时间**，App 只校验
- V1 只新建，不改已有

用户真实样例（用于测试）：
- 「周五17点E栋104考试」→ 事件型
- 「12.03E栋103听讲座」→ 事件型，月.日简写

## 七、课程导入（用户期望有，但 V1 不做）

用户明确希望"导入"，不手填二三十门课。三个方案：

| 方案 | 成本 | 风险 |
|---|---|---|
| **A. AI 粘贴解析**（推荐） | 低——复用已有 AI 模块 | 依赖教务系统页面能复制出文本 |
| B. 模拟登录教务系统抓取 | 高 | 验证码、加密、账号合规问题 |
| C. iCal / 课表分享码 | 中 | 得先有别人做好格式 |

建议走 A：把课表文本粘给 AI，让它输出课程 JSON。V3 实现。

## 九、分发方式（2026-11-21 确定）

用户选择：**发 APK 给朋友，各用各的**。不共享数据、无后端、无账号体系。

- 数据各存本地；AI key 各自在设置页填写，不填也能用纯待办功能（AI 入口提示"先去设置填 key"）。
- **必须用 release 签名打包**（debug 签名不可分发，且 debug 包性能差、体积大）。
- **keystore 文件与密码绝不可进 git**，且必须单独备份——**一旦丢失就无法更新已安装的 App**，朋友只能卸载重装，数据全丢。
- 分发：微信传 APK → 朋友手机允许"未知来源"安装。

## 十、版本规划

| 版本 | 范围 |
|---|---|
| **V0** | 输入框 + 时间选择器 + 到点真的弹通知。**无列表、无存储、无 AI**——只验证提醒链路 |
| **V1** | 日程列表 + 三类条目 + 完成打勾 + 本地存储 + 手动录入 |
| **V2** | 课表网格 tab + AI 对话录入 + 硬提醒 |
| **V3** | 重复规则、提前量、贪睡、课程导入、优先级标签 |

## 十一、技术要点备忘

1. **相对时间**：请求里必须注入"今天是 YYYY-MM-DD 星期X"，否则"下周三""12.03"全算错。
2. **结构化输出**：让模型返回 JSON（JSON mode / function calling），Frontend 直接渲染，不要自由文本+正则。
3. **API key**：不写死、不进 git；客户端存 key 有反编译风险 → 设额度上限、用便宜模型。
4. **周期展开**：列表视图要把"每周一 08:00"展开成具体日期再排序，这是课程进列表的前置逻辑。
5. **环境**：JDK 17 未装；本机 GitHub 不通（Flutter/Android SDK 官方源实测可通，不受影响）。
