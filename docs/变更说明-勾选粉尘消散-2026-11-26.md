## 1. 一句话

勾选完成动画从"手搓假粒子（灰色圆点飞散）"换成 **GPU fragment shader 把卡片本身碎成粉尘**——卡片自己化掉，不是"卡片消失 + 另撒一把沙"。质感对齐用户给的视频（通知卡片化成极细粉尘飘散）。

---

## 2. 为什么要换

上一版（11-25 手搓假粒子）真机验收后被用户判"做的一坨"。复盘三条问题：

1. 粒子是半径 1~3px 的大圆点、只有 46 粒 → 像撒沙子，不是粉尘；
2. 颜色用了完成态的中性灰，视频里是细粉尘；
3. 卡片淡出和粒子飞散是"两张皮"——卡片是卡片、点是点，看着不像碎裂。

第 3 条是根因：**手搓粒子无法让"卡片本身"碎掉**。所以去 GitHub 找现成方案，找到 `disintegrate`（GPU shader，把 widget 当纹理逐像素拆成颗粒）。

---

## 3. 依赖处理：源码抠进项目

`disintegrate`（github.com/yunusemrealpak/disintegrate，MIT）**没有发布到 pub.dev**（404），star 仅 2，是个实验仓库。两种依赖方式都不稳：

- pub 依赖：不存在；
- git 依赖：依赖一个小仓库，随时可能删库/改 API。

决定**把源码抠进项目本地**：

| 文件 | 来源 | 改动 |
|---|---|---|
| `app/lib/widgets/disintegrate/disintegrate.dart` | 原 `lib/src/disintegrate.dart` | 无 |
| `app/lib/widgets/disintegrate/disintegrate_program.dart` | 原 `lib/src/disintegrate_program.dart` | shader asset 路径 `packages/disintegrate/shaders/...` → `shaders/disintegrate.frag` |
| `app/lib/widgets/disintegrate/index.dart` | 新建导出入口 | 导出上面两个 |
| `app/lib/widgets/disintegrate/LICENSE` | 原 LICENSE | 无 |
| `app/shaders/disintegrate.frag` | 原 shader | 无 |

零第三方依赖、完全自主。`app/pubspec.yaml` 加 `flutter.shaders` 声明；`main.dart` 启动时 `await DisintegrateProgram.preload()`（try-catch，不支持的设备吞掉错误）。

**硬前提**：shader-backed `ImageFilter` 是 Impeller 特性，需 Flutter ≥3.41。本项目 Flutter 3.50.1，Android 默认 Impeller，满足。不支持的后端（web/旧设备）会自动降级为普通淡出，首尾一致不跳变。

## 4. shader 原理（为什么质感对）

不是画 N 个粒子（那样每帧 N 次 draw call 必死），而是**反过来算**：每个输出像素反推自己属于哪个颗粒、颗粒从哪来，去 widget 纹理上采样。成本是表面积，不是粒子数——`particleSize` 从 3 调到 1，颗粒数 ×9 但开销不变，所以能做出"极细粉尘"。

- 颗粒从一侧被扫走（`sweep`），不是整张同时淡出；
- 每粒有自己的朝向、速度、横向游走（`scatter`/`turbulence`），不是"带洞的平移"；
- 颗粒在飞行中缩小（`radius` 从 0.78 → 0.02），是"碎成粉"而不是"磨出洞"。

## 5. 动画时序（总 2.3s）

| 段 | 时间 | 效果 |
|---|---|---|
| ① 散开 dissipate | 0–500ms | 源行 `progress 0→1`，卡片原地碎成粉尘飞散，**下方纹丝不动** |
| ② 收起 collapse | 500–1100ms | 源行 `removeItem` 高度收起，下方滑上来补位 |
| ③ 重组 reassemble | 1100–1900ms | 已完成区插入目标行，`progress 1→0`，粉尘聚成卡片 |
| ④ 高亮 flash | 1900–2300ms | 淡黄高亮 400ms |

`progress` 由 `AnimationController`（`SingleTickerProviderStateMixin`）逐帧驱动，`addListener` 里 `setState` 让 build 把新 progress 传给对应行。`drift` 散开/重组共用同一个值（默认 `Offset(18,56)` 偏右下）——往哪散就从哪聚回来。

### 5.1 关键坑

1. **不能用 `flashKey` 判断勾选**：`schedule_screen._toggleEntry` 先 await 落库+重载、再 setState flashKey，两次更新分开，数据先到那帧 flashKey 还是 null。`_completionKey()` 比 `_rows` 和 next 每条的 state（谁从非 done 变 done）。
2. **数据立即落库，显示冻结 500ms**：勾选瞬间照旧写库，列表 `didUpdateWidget` 进 dissipating 后先 `Timer(500ms)` 按住 `_rows` 不动，下方才不会动；切走页面不丢数据。
3. **先 remove 后 insert，中间留空档**：500ms 到点只 remove 源行；1100ms 到点才 insert 目标行 —— "散完才重组"。
4. **`spread` 必须 `EdgeInsets.zero`**（11-26 真机前的测试抓到）：`spread` 是 `EdgeInsets`，**占布局空间**。源行套上 shader 时若加 padding，高度凭空多出（top10+bottom30=40px），把下方条目顶下去，违背"散开阶段下方纹丝不动"。代价：粉尘被限制在卡片自身矩形内，飞散不出边界，碎裂质感仍在。
5. **勾当天最后一条**：LCS 会把它判成 stable（`[a,b,c]→[a,b,头,c]`），不 remove → 散开后又原样冒出来、也不播重组。`_removePhase` 强制 `stable.remove('entry_$_burstEntryKey')`。
6. **收起阶段 progress 必须保持 1**（11-26 真机验收后用户肉眼抓到）：最初 `_dissolveProgressFor` 在 collapsing 返回 null，源行 shader 被摘掉 → 卡片变回完整不透明卡片"复活"，再被 AnimatedList 的 `Opacity(t)` 淡出动画隐去一次。观感就是**"粉末散了 → 卡片又冒出来 → 再隐去"**。修法：collapsing 阶段返回 1.0（DisintegrateEffect 内部 Opacity(0)，卡片始终不可见），收起只靠 `heightFactor` 收空高度。`dissolve_test.dart` 钉住"收起阶段 progress≈1.0"。
7. **shader 实例不能复用**：`ImageFilter.shader` 比较相等时会跳过重绘，原地改 uniform 不刷新屏幕。抠进来的代码用两个 shader 实例交替，无每帧分配。
8. 动画期间到来的 ticker 更新暂存 `_deferredNext`，序列跑完再收敛，避免打断 `AnimatedList` 内部计数。
9. 切日期不播：列表 key 带日期，换日期整页换实例。
